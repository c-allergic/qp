# qp · 追问树

**读论文、啃新东西的时候，你一路追问下去，等搞明白回头一看 —— 主线没了。**

`qp` 把这些追问记成一棵树：每个气泡是你**当时的那句原话**，根节点永远钉着你最初想问什么。
它不是待办清单，也不是思维导图工具，而是一个**「我为什么会问这个问题」的记录器**。

> 🔗 项目主页（含可点的功能演示）：<https://c-allergic.github.io/qp/>

## 为什么做这个

提问式学习有一个绕不开的坑：

> 为了搞懂 A，你去查 B；为了 B，又得先弄清楚 C……等你终于明白 C，已经想不起来自己为什么要出发。

普通的笔记只留下**结论**，"我当时卡在哪、为什么会问到这里"这一层被丢掉了 ——
而那恰恰是下次复习、或者同一个知识点再卡住时最值钱的东西。

所以 `qp` 做了一个很具体的取舍：

- **根节点永远是你最初的问题**，随时能跳回去；
- 每个子节点记的不是"子议题"，而是"**父节点里哪个说法我没懂**"；
- 一条分支搞懂了就**收口**，写下卡点和结论，一眼能看出哪条路已经走通。

## 功能

### 树：一层层追问下去

点气泡上的 `＋`，气泡**原地**变成输入框，写完回车就长出一个子节点。
任何节点都能加子节点（不限于叶子），所以树不会退化成一条链。

| 操作 | 效果 |
|---|---|
| 光标移到气泡上 | 浮出 `＋` 加子问题 / `✎` 改原话 / `💬` 丢进对话 / `✕` 删这棵子树 |
| 按住气泡拖动 | 节点自由移动，连线实时跟着变；落点会被记住 |
| 点气泡 | 切焦点，从根到它那条路加深，右侧面板跟着换 |
| 右上「重置布局」 | 一键把所有气泡放回自动位置 |

### 收口：卡点 / 已明白

一条分支想通了，就在右侧填「**卡点**」（父节点里哪个说法没懂）和「**已明白**」（一句话结论），
点「收口」。收口的分支在树上打 `✓`，一眼能看出哪些路已经走通。

> 局部小结就落在节点的「已明白」里，不必另开一篇笔记。

### 笔记：和树并列的另一种文档

> **树 = 你还没想通、要一层层追下去的东西。笔记 = 你已经想通、要成篇写下来的东西。**

右上「＋ 笔记」新建 markdown 笔记，写的时候有预览、自动保存（⌘S 立即存）。
树和笔记存在同一个文件里，但互不干扰。

### 图片

`⌘V` 直接粘贴截图 → 新建一个图片节点（也可以 `qp img`）。
图片单独按内容哈希落盘（同一张图只存一份），可以给它写描述，导出时一并带上。

### 对话（可选）

右栏第二个页签：多轮 AI 聊天，**流式**输出、**随时可停**（停止会同时断掉上游，不继续烧额度）。
点气泡上的 💬 会把那句原话丢进输入框，你接着问。

### 导出 / AI 梳理问题脉络

顶栏「导出」有两种走法：

- **直接导出 md** —— 把这棵树导出成 markdown，一键下载；
- **AI 梳理问题脉络** —— 让模型读完**整棵树**，把你**想到过哪些问题、每个后面跟着什么回答或更深的追问**
  列出来。结果铺在一个**可编辑**的框里，你改完再点「保存 md」（**不会自动落盘**）。

```markdown
1. **SAM 凭什么零样本**
   - 回答：它用自动 mask 生成，不需要人工 prompt
   - 更深的问题：那 zero-shot 覆盖到什么程度
2. **加权之后 loss 怎么改**
   - 回答：把 mask 当权重乘进逐像素 loss
```

### 分享一份只读快照

```bash
qp render     # 写出 .qp/index.html —— 自包含、可离线打开、无需服务
```

发给别人或者存档，对方直接双击就能看你那棵完整的树。

### 双击打开 / 项目管理器

```bash
qp install-app    # 生成 ~/Applications/qp.app，之后双击就用
qp home           # 项目管理器：把本机所有带 qp 的项目列出来，点一下进
```

## 安装

### 环境需求

| | 需要 | 说明 |
|---|---|---|
| 系统 | **macOS** | 原生窗口、双击 app、项目管理器的文件夹选择都依赖 macOS 自带能力。命令行和浏览器界面本身是跨平台的，但没在 Windows / Linux 上验证过 |
| Python | **3.8+** | 系统自带的就够，**零第三方依赖** |
| 浏览器 | 任意（推荐 Chrome） | 用来开界面；`qp.app` 走系统原生窗口，不依赖 Chrome |
| pywebview | 可选 | `pip install pywebview` 后 `qp app` 能开原生窗口（没装会自动退回 Chrome） |
| 模型端点 | 可选 | 「对话」和「AI 梳理」需要，其余功能**完全不联网** |

### 装

`qp` 就是三个文件（`qp.py` + `qp-ui.html` + `qp-home.html`，**必须放在同一个目录**），加一条软链：

```bash
# 1. 随便找个地方放
mkdir -p ~/apps/qp && cd ~/apps/qp
#    把 qp.py / qp-ui.html / qp-home.html 放进这个目录

# 2. 加一个全局命令（把路径换成你放的位置）
ln -sf ~/apps/qp/qp.py /opt/homebrew/bin/qp      # Intel Mac 用 /usr/local/bin

# 3. 在你要读论文的那个目录里初始化
cd ~/Documents/我在读的论文
qp init
```

> 软链是软链也没关系：`qp` 用 `realpath` 定位自己的目录，所以照样能找到旁边的模板文件。

### 用

```bash
qp new "saliency 加权到底是怎么做的" --source "arXiv:2410.10877 p.5"
qp add @ "用 SAM 提 mask 那步，SAM 不是要 prompt 吗，这里凭什么直接用"
qp add @ "那它的 zero-shot 到底覆盖到什么程度"
qp tree                 # 看一眼
qp ui                   # 打开图形界面（推荐）
```

`@` 表示"当前焦点节点"，所以连着 `qp add @ "..."` 就是一层层往下追。

收了这条分支、准备回主线：

```bash
qp close @ --blocker "父节点默认 SAM 能零样本直接用，没说前提" \
           --resolution "它用自动 mask 生成，不需要人工 prompt，但域偏移明显"
```

### 配模型（可选）

```bash
qp llm --list                                        # 看有哪些预设
qp llm --preset zhipu --key sk-xxx --global           # 配一次，所有项目共用
qp llm --test                                        # 真发一句，顺便看延迟
```

不配也能用**全部功能**，只是「对话」和「AI 梳理」要你自己写。
也可以手写 `.qp/config.json`，或指向本地 Ollama。

## 常用命令

| 命令 | 作用 |
|---|---|
| `qp init` | 在当前目录建 `.qp/` |
| `qp new "<原话>" [--source S]` | 新建一棵树（根节点 = 你最初想问什么） |
| `qp add [<id>] "<原话>"` | 加子问题；省略 id 就挂到当前焦点 |
| `qp edit <id> "<原话>"` | 改某个节点的原话 |
| `qp close <id> [--blocker B] [--resolution R]` | 收口：记下卡点与已明白 |
| `qp rm <id>` | 删掉一个节点及其整棵子树 |
| `qp ls` / `qp tree` / `qp path <id>` | 列 id / 打印 ascii 树 / 打印从根到它的路径 |
| `qp render` | 写出只读快照 `.qp/index.html` |
| `qp md [-o FILE]` | 导出 markdown |
| `qp note "<标题>"` / `qp notes` | 新建 / 列出 markdown 笔记 |
| `qp img <id> <file...>` | 给节点贴图片 |
| `qp ui` | 起本地图形界面 |
| `qp home` | 项目管理器 |
| `qp app` / `qp install-app` | 原生窗口打开 / 生成可双击的 `qp.app` |
| `qp help` | 全部命令 |

## 数据在哪 / 隐私

- 你写的东西全在**运行 qp 的那个目录**下的 `.qp/` 里（隐藏目录，跟 `.git` 一个道理）。
  结构是一个纯 JSON 文件，图片按内容哈希单独落盘 —— 可以直接 `cat`、手工改、`git diff`。
- **没有账号、没有云同步、没有遥测。**
- 只有「对话」和「AI 梳理」会把内容发出去，而且是发到**你自己配的那个端点**；不发请求的其它功能完全离线。
- 对话历史存在浏览器本地（localStorage），不落盘、不上传。
